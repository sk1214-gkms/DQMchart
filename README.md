# 配合チャートメーカー

ドラゴンクエストモンスターズの配合チャートを作成するWebアプリ。
**シリーズ10タイトル・5,715体**に対応し、配合方式の違う3方式を同じエンジン基盤で扱う。
次回作 DQM4 は DQM3 と同方式と想定し、データを足すだけで対応できる設計にしている。

## 起動

```
cd web
npm ci
npm run dev   # → http://localhost:3000
```

## テスト・品質ゲート

```
cd web
npm test         # vitest（配合ルールエンジン＋実データ検証＋手順の妥当性）
npm run lint     # eslint
npm run typecheck # next typegen + tsc --noEmit
npm run build    # 本番ビルド検証
npm run verify   # 実ブラウザで全タイトルのチャート生成を確認（別途 npm run dev が必要）
```

`npm test` はマスタデータの検証も兼ねていて、実行すると次のレポートが更新される。

- `web/docs/未到達モンスター.md` — 入手できないモンスターと、その原因
- `web/docs/データ検証レポート.md` — データの矛盾（ランク・位階の逆転など）

`npm run verify` はPlaywrightを使うが、ブラウザのダウンロードが社内プロキシで通らないため
Windowsに入っているEdgeを `channel: 'msedge'` で使っている。

## 設定

`web/.env.example` をコピーして `web/.env.local` を作る。
現時点で必須の環境変数はない（Supabase導入時に追記予定）。

## 主な機能

| 画面 | 内容 |
|---|---|
| `/simulate` | 配合シミュレータ: 親2体 → 子候補（配合方式に応じて計算＋特殊配合） |
| `/auto` | 自動チャート生成: 目標モンスターから配合ツリーを逆算。配合なしで入手できるモンスターが葉になる |
| `/editor` | 手動チャートエディタ: 配置・接続して配合計画を作る。ルールエンジンで成立判定 |

共通の使い勝手:

- 画面上部のタイトル切替で対応タイトルを選ぶ（発売順に並ぶ。設定はブラウザに保存）
- モンスター選択は名前・系統・ランクで絞り込める
- フロー図は縦（親が上）／横（親が左）を切り替え可能
- チャートはPNG画像として保存できる（表示位置や拡大率に関係なく全体を書き出す）
- 自動生成では「▶」が付いた葉ノードを押すと、そのモンスターを配合で作る手順を展開できる
- 手数が多いモンスターはツリー表示で親子関係を追える（同じモンスターの2回目以降は畳む）
- 位階配合の手順は「○○系の位階△△以下」のように条件で示し、具体的な候補は開いて見られる
- 作れないモンスターは理由を説明する（配信終了なのか、素材が手に入らないのか）

## 構成

### 配合ルールエンジン `web/src/lib/engine/`

UI非依存の純粋ロジック。タイトルごとに `BreedingRuleset` 実装を追加し `registry.ts` に登録する。
UIやチャート描画は方式の違いを知らないので、**新タイトル対応で画面側の変更は不要**。
実際、ジョーカー1〜3プロ・テリワン3D・イルルカ3DSの7タイトルを足す間、
エンジンの新規実装は1つも要らなかった。

**DQM3方式** (`dqm3.ts`)
- 通常配合は「系統ペア×ランク」テーブル参照。親のランクが違えば両方のランクの表から選べる
- 親自身の種族も常に子候補に含まれる（同系統同士では親のどちらかしか生まれない）
- 通常配合では親よりランクの高い子は生まれず、ランクアップは特殊配合のみ

**位階配合方式** (`tier.ts`／ジョーカー1・2・2プロ、テリワン3D・SP、イルルカ3DS・SP)
- 全モンスターに通し順の「位階」があり、子は位階の並びから決まる
- 同系統配合 → 強いほうの親より位階が1つ上の、同じ系統のモンスター
- 異系統配合 → ①父の系統で強い親の1つ上 ②母の系統で強い親の1つ上 ③系統組み合わせ表で決まる別系統で、**弱いほうの親**の1つ上
- 系統の最上位を超える子は生まれない（位階の打ち止め）。打ち止めの位置は作品ごとに違う
- 系統の掛け合わせ表はジョーカー1からイルルカまで変わらないので使い回している
- 位階表が途中までしか公開されていない作品（ジョーカー1）では、
  表より上のモンスターの位階を「表のどれよりも上」として扱う。
  最弱として扱うと、上位モンスターを弱い親とみなした嘘の配合が出てしまう

**ジョーカー3方式** (`dqmj3.ts`／ジョーカー3・3プロ)
- 位階を計算式で求める。親2体の位階から3通りの子の位階が出る（系統は関与しない）
- 逆算は総当たりではなく式を逆に解く。片方の親を決めれば相手の位階がほぼ一意に定まるので、
  安く用意できる親から順に試し、最良を超えられなくなったら打ち切る

逆算プランナーはどの方式も、入手できるモンスターを起点にコストが下がらなくなるまで
繰り返し緩和する方式（最短経路の緩和法と同じ考え方）で最小手数を求める。
配合の依存は循環しうるため、素朴な深さ優先探索では到達可能な経路を取りこぼす。

| DQM3 (`dqm3.json`) | DQM3方式 | 526 | 372 | 100% |

**到達率100%でない分は、すべて配信・すれちがい・コラボの終了が原因**で、データの不足ではない。
「入手方法が分からないモンスター」は全タイトルでゼロ。内訳は `web/docs/未到達モンスター.md` を参照。

- 攻略サイトから収集した実データ。誤りに気づいたらJSONを直接修正してよい
- 配合以外の入手手段は `acquisition` で区別
  （`wild` 野生／`egg` タマゴ／`event` イベント・配信／`transfer` 他作品から連れてくる）
- 今から入手できないものは `discontinued` で区別する。調べても解決しないものを見分けるため
- 位階配合タイトルの `tier` は**ランク順とは一致しない**。実際の位階番号を使うこと

### 作品間の引っ越し

シリーズは前作から次作へモンスターを連れていける。ある作品で配信終了により入手できなくても、
連れてこられる作品側で手に入るなら今でも入手できる。経路は `transfersFrom` に持たせてある。

```
ジョーカー2 ⇄ ジョーカー2プロ（通信交換・双方向）
ジョーカー2/2プロ → テリワン3D → イルルカ3DS → ジョーカー3
ジョーカー3・イルルカ3DS ────────────────────▶ ジョーカー3プロ（ランク制限なし）
```

ランク上限は**連れていく先のランク**で判定する（作品によって同じモンスターのランクが違う）。
イルルカ3DS→ジョーカー3は「両方の作品でAランク以下」が条件なので、`maxSourceRankId` で
連れてくる元の上限も見る。SP版（テリワンSP・イルルカSP）に引っ越し機能はない。

### ツール `web/tools/`

| ツール | 用途 |
|---|---|
| `build-title.mjs` | 収集データから新しいタイトルのマスタデータを作る |
| `apply-supplement.mjs` | 既存タイトルに入手方法・配合レシピを追記する |
| `apply-transfers.mjs` | 引っ越し経路をたどって入手方法を書き込む |
| `verify-app.mjs` | 実ブラウザで全タイトルのチャート生成を確認する |
| `engine-bridge.mjs` | ツールからTypeScriptの配合エンジンを呼ぶ（jiti経由） |

到達判定をツール側に書き写すと本体とずれるので、必ず本物のエンジンを呼ぶ。
エンジンはデータのオブジェクトをキーに逆算結果をキャッシュするため、
書き換えたあとは新しいオブジェクトとして渡す必要がある。

### 既知の課題

- チャート保存はブラウザ内のみ。デバイスをまたいだ共有はできない
- ジョーカー2プロの進化配合（強○○・最強○○）は同じ種族の能力強化版で、
  位階表にも載らないためデータに含めていない。ジョーカー2無印のほうは
  独立したモンスター（7系統×2の14体）なので登録している
- テリワン3Dの究極配合は新種族を生まないためデータに含めていない
- 「〜の書」系は配合の副産物（余らせたスキルの数で誕生）で親の組み合わせでは
  表せないため、レシピではなく入手方法として登録している
